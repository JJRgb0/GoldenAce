# Golden Ace Arcade
#### Video Demo:  <URL https://youtu.be/159Orw_y-Bw>
#### Description: A retro 3d web arcade that runs some classic games.

### Project structure
        This project contains an api and client folders which are stored the backend and frontend files respectively.
        Acessing the API folder there is a dict folder (only a folder where build files are sent after running the build), a prima folder that stores the config for my prisma database and a src folder containing my backend api. In prisma it's configured the schema of my database in the shema.prisma file and the migrations are kept in the migrations folder. The src folder is organized by the controllers that stores functions to interact with the database via services in which are built the prisma notaion to interact with it, and the routes which handles the http requests. The server was built with NodeJS.
        The client folder has some configuration for both typescipt and vite and of course NodeJS. In the public folders the static files like images and videos are stored. In the src folder is where all the logic of the frontend happens.
        There's only a file to handle the css called global.css in due to the use of tailwind. Redux is used to keep global states such as what screen is being displayed (url paths are not being used because the arcade doesn't work properly if the page reloads) the user binds or what buttons are being pressed. There are also some utils folders like lib which has some functions and objects that are ofter called in the components and hooks that holds helpful functions too in the context of React usage.
        Lastly, the components folder is where all the displayed info is stored. The games folder stores the components that returns iframes and configure the games. The layout stores the react-three components and render the 3d i the browser. The pages folder is where the static pages that are displayed inside the arcade are being stored and finally, the utils folder stores some utillity components such as the Not Found page component or the manual one.

### Usage
        When the user acess the site it's shown a manual that teaches how to turn on the arcade and what are the default binds for the joystick and the buttons so the user can turn it on. Inside of it the user can quit the arcade, configure it or play some game. If the enter the options menu it will be possible to change the overall volume of the arcade (not including the pressing button sound because it's not part of the arcade) and test it using the bottom button, change the brightness of it (not being possible to set it to 0) and customize his binds that are holded in the local storage and being tracked by redux. These values are kept in the localstorage so the user will retrieve these configs even if he quit the arcade site.
        At the moment there is only one game available to play which is the snake one and if the user open it it will be possible to play, quit and check the top 10 scores table. You can move the snake using the joystick and if the user complete the game he will rebirth faster so there isn't a maximum score. Once he gets a top score, that is verified via http request to the database using the backend functions, he'll be promped with a virtual keyboard and optionally he'll be able to register a name in the table aside of his score.
